Arquitectura del RAG

Tres vistas del mismo sistema: dónde corre cada pieza, qué pasa cuando subes un documento y qué pasa cuando haces una pregunta.

  • Código del proyecto
  • Datos o pasos intermedios
  • Servicio externo o límite de red
  • Abstención

1. Dónde corre cada pieza

Dos contenedores en la red interna de Docker Compose. El navegador solo ve a Streamlit; Streamlit solo ve a la API; la API es la única que toca Chroma y Google AI.

2. Qué pasa cuando subes un documento

Es la ruta POST /ingest. Se hace una vez por documento y deja el índice listo en disco. Cada módulo transforma el dato y se lo pasa al siguiente.

3. Qué pasa cuando haces una pregunta

Es la ruta POST /query. Primero recupera, después genera, y hay dos puntos donde el sistema puede decidir abstenerse en lugar de inventar.
